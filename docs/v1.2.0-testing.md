# v1.2.0 testing handoff

Branch: `feature/v1.2.0-personal-gifting`. This is a minor release: additive features, with existing short links and legacy fragment links retained. Do not merge or promote to production until the checks below are complete.

## Isolated setup

1. Use a separate Supabase test project. Apply `001_gifts.sql`, `002_security.sql`, then `003_personal_gifting.sql` from `supabase/migrations`. For an existing test project already on v1.1.0, apply only `003`. Do not apply this migration to the production project during testing.
2. Configure the preview's `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` for that test project. Set email credentials for a test mailbox/provider, and `PUBLIC_SITE_URL` to the preview's origin. Only `VITE_` keys may reach browser code. Never commit `.env`.
3. Set a random `CRON_SECRET`. The daily `/api/maintenance` job checks database availability and retries failed opened emails. Vercel schedules only run on production deployments, so call this endpoint manually with `Authorization: Bearer <CRON_SECRET>` when testing a preview. A failed delivery can be reclaimed after ten minutes.
4. For local full-stack checks use `vercel dev`. Plain `npm run dev` serves the frontend only; `/api/send-gift`, `/api/gift-event`, and maintenance need Vercel functions.
5. Run `npm test`, `npx playwright install chromium`, `npm run test:e2e`, `npm run build`, `npm run lint`, and `npm audit`. Browser tests run at mobile and desktop sizes with synthetic microphone input. Standard regression tests use mock backend responses; integration tests connect the actual API handlers to embedded PostgreSQL through a PostgREST-shaped adapter, with mail delivery simulated. No test uses the configured live project. Database tests execute all three migrations with Supabase storage/role fixtures; the random-byte function is a test stub.

## Manual acceptance checks before merging

- Schedule a gift two minutes ahead in Manila time. Visit its link before unlock: only the locked screen/countdown should appear. Inspect the `get_gift` response: `data` must be null. Change the phone clock forward and try again. After the actual server deadline, the gift should open within the next fifteen-second poll. Repeat with a bundle and after reloading.
- Confirm ordinary gifts open immediately and old v1.1.0 links still work. Test a legacy fragment link, a mistyped ID, a truncated fragment, and a disconnected network. Check the friendly missing-gift and retry screens.
- Create a gift with opened notices off. No sender email should be saved. Enable the checkbox and add a test address: a normal gift visit should show the recipient disclosure; tapping Open sends one email. Reopen, reload and open in another tab: no further notice should be queued. Link preview requests and locked visits should never send one.
- Simulate a mail provider failure; confirm the gift still opens and its notification stays queued. After ten minutes, call maintenance and check delivery. Disable the option and save: the sender address should become null and pending deliveries should no longer be claimed. Resend has a stable idempotency key. Gmail retries can duplicate a notice if the provider accepts it immediately before a process failure; exactly-once delivery cannot be guaranteed across that boundary.
- Enable replies, send an emoji and a short message from a second device, and use the private edit link's Check replies button to read them. A wrong edit token must return no replies. With replies disabled or while locked, posting a reply must fail. Test the 500-character and ten-replies-per-gift-per-day limits.
- On a phone, place a new flower, move an existing stem into an occupied spot, shuffle, remove stems, then save/reload/reopen the edit link. Preview and downloaded PNG/JPG must preserve the arrangement. Try all wraps.
- Open a fresh letter and bouquet form. Message fields should be empty, with no occasion selector or generated starter text. Existing user drafts must remain intact. At the fourteen-flower maximum, the flower picker should stay compact on mobile; tap a flower to select it, choose a spot to move it, or use Remove flower.
- Make a letter → bouquet → quiz bundle. Reorder and remove/add gifts, preview each, share the single link, then edit and save. The recipient should step through the saved order. Include photo/audio gifts; try the eight-gift maximum. Bundles cannot contain another bundle.
- Send three gift emails. The fourth attempt must be limited. Try a private tab/cleared browser storage and a second gift from the same IP: the server limit must persist. The per-gift/IP window resets after three hours; the recipient window is three attempts per day. Failed delivery attempts consume a slot deliberately to prevent concurrent-send bypasses. Copy link stays available.
- Paste a preview link into Messenger/iMessage and inspect its card. The static 1200×630 card contains no names, messages, unlock time or private content. `PUBLIC_SITE_URL` makes the image URL absolute outside Vercel; Vercel builds fall back to `VERCEL_URL`. Messaging services control image caching and when they refetch.
- Confirm `/api/maintenance` refuses missing/wrong secrets. Review its scheduled invocation logs after release. Open an older keepsake after a quiet week. This elapsed-time check remains pending: a health ping is not an uptime guarantee on Supabase's free plan.
